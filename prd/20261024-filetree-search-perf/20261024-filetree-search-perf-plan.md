# 文件树筛选：慢遍历导致的"无结果"假象

> 实现记录：同目录 `20261024-filetree-search-perf-modification.md`。

## 问题

文件树筛选框输入文件名后长时间（十几秒）显示「无匹配文件」，结果才突然出现，看起来像筛选失效。

## 诊断（CDP 实测）

筛选逻辑本身正确，真实原因是 `walk` 串行遍历：

- `await readDir(dir)` 逐目录串行，每个 Tauri IPC 往返约 2.7ms；
- 实测工作区 5603 个目录 / 11137 个文件，完整遍历 **15 秒**；
- 遍历期间 `searchResults` 为空，UI 显示「无匹配文件」；
- 附带 race：遍历期间继续输入，旧查询的结果完成后会覆盖新查询的结果。

## 方案

- `walk` 改为按层并行：每层目录按 32 并发分批读取，大幅缩短总耗时。
- 引入取消令牌 `searchSeq`：每次新搜索（或清空、组件卸载）令牌 +1，`walk` 在每层/每批后检查，失配立即中止；完成的旧搜索凭令牌校验丢弃结果，杜绝旧覆盖新。
- 新增 `searching` 状态：遍历期间显示「搜索中…」，有结果才显示结果，不再用「无匹配文件」误导；清空输入时取消进行中的搜索。
- `SEARCH_SKIP` 扩充常见生成目录：`.venv`、`venv`、`__pycache__`、`.idea`、`.cache`、`.mypy_cache`、`.pytest_cache`、`target`、`build`。

## 验证

- `pnpm build` 通过。
- CDP 实测（真实工作区）：输入到出结果 **14.5s → 2.0s**，期间显示「搜索中…」；命中项与修复前一致（19 项）。
- 竞态验证：快速输入 `zzznomatch` 后改 `manual`，最终结果全部含 `manual`，无旧结果残留。
